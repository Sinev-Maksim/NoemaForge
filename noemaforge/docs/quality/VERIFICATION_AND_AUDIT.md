The main omission from 0.29.10 was packaging scope, not live-host deletion.

## Fragment 4: CODE DEV QA SUBTEAM 0.31.0

### NoemaForge 0.31.0 — Code development QA sub-team

Goal: every code-producing pipeline can hand the result to a QA sub-team before the next participant.

Default invariant:

```text
single active LLM
sequential reviewer execution by default
reviewers must not equal the producer model
```

Commands:

```bash
noemaforge qa code team --producer qwen25-coder-14b --json
noemaforge qa code run --project . --producer qwen25-coder-14b --json
noemaforge qa code list
noemaforge qa code show <run_id>
```

The run creates:

```text
run.json
scan.json
local_checks.json
proposals/<reviewer>.json
consensus.json
next_participant_handoff_context.md
next_participant_handoff_context.json
next_participant_handoff_context.json.sha256
```

The consensus layer records:

- what each reviewer proposed;
- which findings had multi-reviewer agreement;
- which findings were unique;
- recommended test commands;
- handoff to tester/integration tester.

Recommended sub-team size is 2 reviewer models, selected from code-capable models to maximize correctness and diversity while excluding the code producer.

## Fragment 10: RELEASE AUDIT 0.31.08

### NoemaForge 0.31.10 Release Audit — recursion, first-start, GUI timer

#### Purpose

0.31.10 is a release-audit stabilization build after the live NoemaForge debugging cycle. It focuses on recursion prevention, first-start predictability, GUI timer autostart, ToolProxy/SEL safety and policy invariants.

#### Confirmed historical bugs addressed

##### 1. Full installer recursion

Observed in 0.31.10:

```text
setup.sh -> install_noemaforge_0.31.10_mvp.sh -> setup.sh -> ...
```

0.31.10 keeps the 0.31.10 full-installer fix and adds a release audit:

```text
setup.sh may delegate once to install_noemaforge_0.31.10_mvp.sh
install_noemaforge_0.31.10_mvp.sh must never call setup.sh
NOEMAFORGE_SETUP_DEPTH blocks re-entry
noemaforge-recursion-audit.sh checks the package statically
```

##### 2. Public `noemaforge` wrapper recursion

Observed risk:

```text
/usr/local/bin/noemaforge wrapper -> /opt/noemaforge/bin/noemaforge -> public wrapper path -> hang/recursion
```

0.31.10 policy:

```text
/opt/noemaforge/bin/noemaforge is canonical implementation
/usr/local/bin/noemaforge is symlink to /opt/noemaforge/bin/noemaforge
/usr/local/sbin/noemaforge is symlink to /opt/noemaforge/bin/noemaforge
/usr/bin/noemaforge is symlink to /opt/noemaforge/bin/noemaforge
/bin/noemaforge is symlink to /opt/noemaforge/bin/noemaforge
helpers/noemaforge is not installed as public noemaforge
```

`NOEMAFORGE_SELF` used by systemd-run now resolves from `$ROOT/bin/noemaforge`, not from `/usr/local/bin/noemaforge`.

##### 3. `gui_start` command surface

`noemaforge gui_start` previously behaved as help/runbook or via a wrapper layer. 0.31.10 keeps native command support inside `/opt/noemaforge/bin/noemaforge`:

```text
noemaforge gui_start --help
noemaforge gui-start --help
noemaforge gui start --dry-run
sudo noemaforge gui_start --wait
sudo noemaforge gui_start --restart --wait
```

The command starts Debian GUI through GDM/display-manager and does not start NoemaForge LLM.

##### 4. GUI autostart race

Direct `WantedBy=graphical.target` startup caused boot-time races:

```text
noemaforge-autostart-gui.service starts too early
waits for display-manager
GUI is not stable yet
service fails or contributes to bad first-start behavior
```

0.31.10 keeps timer-based autostart:

```text
noemaforge-autostart-gui.service is static/timer-triggered
noemaforge-autostart-gui.timer is enabled for GUI mode
readiness checks happen inside autostart-safe and are non-fatal
```

The strict NVIDIA/GDM `ExecStartPre` checks were removed from the GUI delay drop-in, because they can turn a delayed display stack into a failed unit.

##### 5. Runtime/LLM policy

Confirmed policy:

```text
gui mode:
  runtime/toolproxy allowed
  CPU bootstrap LLM optional only by profile
  default runtime_only
  heavy LLM manual-only

wogui mode:
  CPU bootstrap LLM allowed
  heavy LLM manual-only
```

`runtime_only` must not start `llama-server`.

##### 6. ToolProxy + SEL

0.31.10 keeps the live fixes:

```text
noemaforge-sel-fix runs as root preflight
ToolProxy runs as noemaforge
current-day SEL segment files are repaired for append access
historical sealed logs are not recursively mutated
```

#### New release-audit command

```bash
noemaforge/tools/prep/noemaforge-recursion-audit.sh /path/to/package
noemaforge/tools/prep/noemaforge-recursion-audit.sh --json /path/to/package
```

It checks:

```text
current installer does not call setup.sh
setup has recursion guard
public noemaforge helper is not installed as authoritative CLI
canonical CLI does not delegate to public noemaforge wrappers
GUI autostart service has no direct Install target
GUI timer points to the GUI service
boot-mode helper does not enable direct GUI service
autostart-safe has runtime_only and heavy-LLM rejection policy
```

## Fragment 16: public mwp shortest path

### NoemaForge public MWP — shortest path

#### Audience

Target audience is broader than engineers: technical enthusiasts who can run Debian/Linux commands but should not need to inspect Python internals or raw curl JSON.

#### Definition of public MWP

A public MWP is not the full autonomous NoemaForge vision. It is:

1. installable on a Debian desktop;
2. uses one local LLM safely;
3. exposes a chat command without JSON/curl;
4. exposes a monitor command;
5. can stop/reboot safely;
6. recommends model size/quantization for the user's machine;
7. includes a clear README, context file and recovery path.

#### Minimal public commands

```bash
noemaforge recommend-model
sudo noemaforge safe-start --wait --restart
noemaforge chat --once "hello"
noemaforge monitor
noemaforge smoke --debug
sudo noemaforge stop
sudo noemaforge reboot-safe
```

#### Do not ship yet

- parallel model runtime;
- autonomous Evolve promotion;
- heavy model auto-start;
- model downloads without clear license/storage prompts;
- GUI killing by default;
- direct writes to Vault while NTFS is dirty.

#### Next engineering milestones

1. Wrap this full release as a deb package.
2. Add `noemaforge doctor` as the single public diagnostic report.
3. Add a minimal TUI or local web shell.
4. Add guided first-run wizard: Vault check, model advisor, choose safe main, safe-start.
5. Add role presets but keep one active model.
6. Add opt-in community role packs in quarantine-first mode.
