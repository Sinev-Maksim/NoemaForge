# NoemaForge 0.33.0 pre-release fix summary

This repo change addresses local, reviewable pre-release blockers found during
the 0.33.0 target-host UAT and the second Codex hardening pass. It does not tag,
push, restart services, change the applied epoch, or mutate target runtime
artifacts.

## First-pass UAT/runtime fixes

- Added read-only UAT artifact helpers in `pre_release_uat_fix_runtime.py`.
- Gateway socket discovery now has a canonical helper order:
  `/run/noemaforge/llm/gateway.sock` first, legacy sockets only as fallback.
- Epoch checks now use `/var/lib/noemaforge/contracts/epochs/current` and
  `/var/lib/noemaforge/contracts/epochs/<epoch_id>`.
- Operator degraded apply location excludes `operator_degraded_apply_plan_*` and
  prefers real apply directories containing apply summary/post-apply artifacts.
- Model-run summaries are derived from raw `model-run-records` shapes instead of
  empty defaults, so `model_runs` and `models_started` cannot be reported as zero
  when raw records exist.
- Runtime finding classification now distinguishes `completed`,
  `partial_valid`, `warmup_failed`, `timeout`, `systemctl_start_failed`,
  `safety-filtered`, and `unknown`.
- Early helper failures can emit JSON and Markdown failure reports.
- The Go LLM gateway exposes `GET /v1/models` as a read-only local model list,
  avoiding a misleading 404 on green-path smoke.
- The UAT subprocess runner keeps source validation and removes the Semgrep
  suppression from the callsite.

## Second-pass hardening fixes

- `brainui.py` static asset serving now resolves paths through a canonical
  containment helper before reading files and rejects traversal/symlink escapes.
- XML parsing surfaces in `privileged_gui_job_runner.py`, `persona_runtime.py`,
  and `glove_agent.py` now prefer `defusedxml` and reject XML entity
  declarations before stdlib fallback when the optional dependency is absent.
- `ci/acceptance_runner.py` no longer imports `xml.etree` for JUnit generation;
  it writes escaped repo-owned XML output directly.
- `prestart.py` canary execution now uses a validated wrapper with suite
  allowlisting, runner/path root validation, strict argv composition, and
  explicit `shell=False`.
- SQL scanner findings were remediated where local and safe by separating
  allowlisted identifiers/order clauses/placeholders from bound values in
  `scan_tg.py`, `vstore.py`, `ui_snapshot.py`, `taskqueue.py`, `task_tools.py`,
  `selftest_runtime.py`, `roadmap.py`, `knowledge/store.py`,
  `knowledge/prep_store.py`, and `knowledge/error_learning.py`.
- GitHub workflow token permissions now default to top-level `contents: read`;
  write permissions remain job-scoped only where the workflow intentionally
  writes comments, issues, workflow dispatches, commits, or wiki content.
- `gateway/inference_service/Dockerfile` pins `python:3.11-slim` to the scanner
  suggested digest.
- Added `noemaforge/docs/security/binary-artifacts-0.33.0.md` to document why
  the gateway binary is shipped and why binary rebuild provenance remains a
  release hardening requirement.

## Code scanning disposition

All 50 operator-collected code-scanning alerts have an explicit local
disposition in `noemaforge/docs/security/code-scanning-0.33.0-disposition.md`.
This second pass fixes safe local code-owned findings and selected workflow/
Docker findings. It does not claim that all alerts are closed: GitHub-side
governance, intentional write-token jobs, pip hash-locking, fuzzing/OpenSSF
signals, and binary provenance remain follow-up items.

## Validation focus

Tests cover the exact UAT regressions from the first pass and the hardening
surfaces from the second pass: static path containment, XML entity rejection,
validated canary subprocess argv, SQL allowlist helpers, canonical socket order,
epoch path resolution, apply-plan directory exclusion, raw model-run summary
extraction, early failure report emission, and `/v1/models` gateway source
contract.
