# NoemaForge Engineering Guardrails v1.0

This package is the reusable source of truth for NoemaForge/Night Watch engineering behavior.

## 1. Recovered agreed rules

### Workspace and evidence
- Work in an isolated worktree derived from an exact base SHA.
- Never mutate the source checkout while evaluating a candidate.
- Existing regression tests are immutable during a repair task.
- Unexpected changed files fail closed.
- Disable/remove generated bytecode before scope comparisons.
- Bind every review/evidence envelope to the exact candidate SHA.
- Preserve failed evidence/worktrees until the evidence package is created.

### Architecture and contracts
- Contracts/schemas are source-of-truth interfaces. Runtime code consumes them; prompts must not silently invent a parallel contract.
- Keep pure routing/policy decisions separate from provider/process adapters and side effects.
- Persona, capability, provider, model/session identity, and readiness are distinct dimensions.
- Providers are late-bound from capability/readiness, not hard-wired into persona identity.
- Skill access is decided from persona purpose + capability + skill danger. Security is not primarily an exception list.

### Review semantics
- Implementer self-review never satisfies an independent review slot.
- A fresh session on the same provider/model is a local co-check, not an independent vote.
- `independence_key` belongs to the real execution identity, not the persona name.
- Git Helper is deterministic integrity/provenance review, not an independent semantic LLM vote.
- Optional reviewers do not block unless policy explicitly requires them.
- CodeRabbit remains conditional for Markdown-only changes, but for code/config/infra it normally binds to the exact candidate SHA.
- A failed review gate short-circuits reproducer, cost estimation, budget routing, and GCP.

### Night Watch order
`finding → work item → minimal fix → local checks → affected review → review gate → reproducer → cost estimate → budget route → GCP gate → formal result → next iteration`

Two ordering rules are hard:
1. fix before reproducer;
2. review before reproducer.

### Self-heal control
- `stagnation_limit_per_task = 4`.
- `stagnation_limit_per_task` is never `0 = unlimited`; it must be >= 1.
- `traversal_depth_limit = 0` means unlimited depth.
- `global_iteration_limit = 0` means no global cap by default.
- A new downstream task receives a new task key and its own stagnation counter.
- Provider/transport/capability failures must be classified separately from a product defect.

### Side effects
- No push/PR/merge/tag/branch deletion/GCP write without the corresponding authorization.
- Do not change PATH, registry, global Git configuration, or global PowerShell execution policy to make a harness pass.
- Discover installed runtimes outside PATH first; use a hash-pinned portable fallback only when host runtimes are unusable.

### Terminal handoff
- PASS/STOP/HARNESS_ERROR must signal readiness.
- Create a compact ZIP/TAR.GZ handoff with terminal report, prompts/agent evidence, candidate patches/proposals, deterministic gate evidence, manifest, and SHA-256.
- Exclude disposable worktrees.
- Print both the local path and a local file URI.

## 2. Clarifications correcting the research report

The deep-research report was useful but several statements must NOT become policy:

1. **`stagnation_limit_per_task=0` is not unlimited.** Only traversal/global limits use 0 as unlimited. Stagnation must be >=1; default 4.
2. **Separate Codex sessions are not independent review.** They are useful local co-checks but cannot satisfy an independent semantic vote.
3. **Do not force POSIX paths for actual filesystem operations.** Use native `Path`/filesystem semantics internally; use `/` for external identifiers, schema values, artifact keys and portable messages.
4. **Do not globally run `Set-ExecutionPolicy Unrestricted`.** Use a process-scoped launcher (`-ExecutionPolicy Bypass`) or signed/policy-compliant scripts.
5. **A local PASS is not “ready to push”.** Remote/exact-SHA review and explicit remote-write authorization still apply.
6. **CRLF warnings are not automatically failures, but stderr is never blindly ignored.** Classify known benign warnings separately from errors.
7. **PowerShell parse PASS is not runtime compatibility proof.** Windows PowerShell 5.1 behavior needs a runtime smoke for used constructs.
8. **Do not ask the user to poll the terminal.** Terminal state must create a readiness signal and a handoff archive.

## 3. New generalized guardrails from the repeated-rake audit

These are recommended additions derived from live failures:

### External-process invocation contract
No unbounded or user/model-generated payload may be transported in argv. Use UTF-8 bytes on stdin, a UTF-8 file, or another bounded structured IPC channel.

The contract has independent readiness dimensions:
`process_launch`, `auth_entitlement`, `input_transport`, `output_transport`, `read_surface`, `mutation_surface`, `structured_protocol`, `quality_calibration`.

### Byte protocol, not host text defaults
Machine protocols are byte contracts. Never rely on the PowerShell/.NET/console default code page for model prompts or structured responses. UTF-8 must be explicit end-to-end and proven with a non-ASCII round-trip canary.

### Attempt accounting
A product repair attempt is charged only after a candidate edit/proposal is successfully materialized and the post-fix deterministic gate actually runs. Transport/provider failures belong to infrastructure recovery, not the product task's stagnation history.

### Prevention beats patching
Every `UAT request findings resolution` must add:
1. the root-cause fix;
2. a generalized static/runtime guard that would have caught the class before user execution.
